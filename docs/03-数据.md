# 03 · 数据：从哪来、怎么洗

> 时间预算 5 小时。这一章之后，你就有自己的数据管道了。

## 一、数据从哪来

| 来源 | 费用 | 优点 | 缺点 |
|---|---|---|---|
| **东方财富接口**（本教程用） | 免费 | 不要 token、字段全、稳定 | 非官方 API，可能变 |
| akshare | 免费 | 封装好，一行搞定 | 依赖 30+ 包，接口常改名 |
| tushare | 免费额度极少 | 数据规范，有文档 | 现在大部分接口要积分/付费 |
| baostock | 免费 | 稳定，适合教学 | 数据更新慢，字段少 |
| Wind / Choice | 几万/年 | 专业级，机构在用 | 学生买不起 |

**为什么本教程直接用 HTTP 接口？**

因为你会看到"数据到底是怎么来的"。所谓 akshare，本质就是把这个请求封装了一下。
40 行代码，你能读懂、能改、能自己加字段 —— 这比会调 `ak.stock_zh_a_hist()` 有价值得多。

### 一个请求长什么样

```python
url = "https://push2his.eastmoney.com/api/qt/stock/kline/get"
params = {
    "secid": "1.600519",   # 1.=上交所，0.=深交所
    "klt": "101",          # 101=日线 102=周线 103=月线
    "fqt": "1",            # 0=不复权 1=前复权 2=后复权
    "beg": "20200101",
    "end": "20241231",
    "fields2": "f51,f52,f53,f54,f55,f56,f57,f59,f61",
}
```

返回的是 JSON，核心字段 `data.klines` 是一个字符串数组，每行逗号分隔：

```
"2024-01-02,1580.66,1550.67,1583.85,1543.76,32156,5440082548.00,2.52,0.26"
 日期       开盘     收盘     最高     最低    成交量   成交额    涨跌幅 换手率
```

**注意顺序：开、收、高、低。** 不是常见的 OHLC，是 OCHL。写错顺序的 bug 非常隐蔽 ——
价格都在同一个量级，不报错，只是你的策略一直在用错误的高低价。

## 二、字段字典

| 字段 | 含义 | 单位 | 用法 |
|---|---|---|---|
| `open` | 开盘价 | 元 | 隔夜跳空分析、开盘策略 |
| `high` | 最高价 | 元 | 突破策略、日内波动 |
| `low` | 最低价 | 元 | 止损触发判断 |
| `close` | 收盘价 | 元 | **最常用**，日频策略的基准 |
| `volume` | 成交量 | 手（100 股） | 量价配合、流动性评估 |
| `amount` | 成交额 | 元 | 比 volume 更可靠（不受股价影响） |
| `pct_chg` | 涨跌幅 | % | 判断涨跌停 |
| `turnover` | 换手率 | % | 活跃度、拥挤度 |

**为什么用成交额而不是成交量？** 因为成交量以"手"计，一只 3 元的票和一只 300 元的票，
同样 1 万手代表的资金量差 100 倍。成交额（元）才是可比的。

## 三、数据清洗：五个必须做的检查

拿到数据先别急着算策略，先做这五件事。**这五步能帮你发现 80% 的数据问题。**

### 1. 检查缺失值

```python
df.isna().sum()
```

有缺失就要想清楚原因：是新股上市？停牌？还是接口返回不全？

### 2. 检查重复日期

```python
df.index.duplicated().sum()      # 必须等于 0
```

接口偶尔会返回重复行，不去重会让收益算错。

### 3. 检查价格逻辑

```python
assert (df["high"] >= df["low"]).all()
assert (df["high"] >= df["close"]).all()
assert (df["low"] <= df["close"]).all()
```

最高价不可能低于最低价。这种检查很土，但能立刻抓出字段顺序错位。

### 4. 检查异常涨跌

```python
extreme = df[df["pct_chg"].abs() > 11]      # 主板超过 11% 就可疑
```

有极端值可能有三种原因：真实涨停（新股/科创板）、数据错误、复权问题。
**逐个看，不要直接删。**

### 5. 检查日期连续性

```python
gaps = df.index.to_series().diff().dt.days
long_gaps = gaps[gaps > 10]        # 超过 10 天的缺口
```

超过 10 天的缺口通常是停牌。停牌期间的数据不能当"连续交易日"处理。

## 四、缓存：为什么必须有

每次跑策略都重新下载数据，有三个问题：

1. **慢** —— 20 只票 × 3 年，每次 20 秒
2. **不稳定** —— 网络一抖，这次跑出来的结果和上次不一样，你无法判断是代码改了还是数据变了
3. **可能被封** —— 频繁请求接口会被限流

本教程用 parquet 缓存：

```python
# src/data.py 里的逻辑
if path.exists():
    return pd.read_parquet(path)     # 有缓存，毫秒级
...
df.to_parquet(path)                  # 第一次下载后存下来
```

**为什么用 parquet 不用 csv？**
parquet 保留数据类型（日期就是日期，不会变成字符串），体积小 3~5 倍，读取快 10 倍。
唯一的缺点是不能用 Excel 打开 —— 但你可以随时 `df.to_csv()` 导出一份。

想强制刷新缓存？删掉 `data/cache/` 目录就行。

## 五、离线模式：为什么必须能离线跑

```python
prices = load_daily("600519", "2020-01-01", "2024-12-31", offline=True)
```

`offline=True` 时会用**合成数据**替代真实数据（几何布朗运动生成的价格）。

这不是偷懒，是两个很实际的需求：

1. **没网也能学** —— 你在高铁上、在图书馆断网，代码照样能跑
2. **结果可复现** —— 合成数据的随机种子由股票代码决定，同一只票每次生成的完全一样。调试策略时，你改一行代码就能确定结果变化是代码引起的，不是数据刷新引起的

**这是一个很重要的工程习惯：把"数据不确定性"隔离掉，你才能调试逻辑。**

## 六、多股票数据：长表 vs 宽表

做单票择时，一张表就够。做多因子选股，你需要处理"一堆票 × 一堆日期"。

**长表（long）** —— 每行一个 (日期, 股票)：

```
date        symbol  close
2024-01-02  600519  1550.67
2024-01-02  000858  135.20
2024-01-03  600519  1559.66
```

**宽表（wide）** —— 行是日期，列是股票：

```
date        600519   000858
2024-01-02  1550.67  135.20
2024-01-03  1559.66  136.10
```

两种都要会：

```python
wide = panel.pivot_table(index=panel.index, columns="symbol", values="close")
long = wide.stack().rename("close").reset_index()
```

**什么时候用哪个？**

- 时间序列计算（均线、动量）→ 宽表，一行代码算全部股票
- 横截面计算（排序、分组、标准化）→ 宽表，`axis=1` 操作
- 存储、筛选、合并 → 长表

**一个常见错误**：用长表做 `rolling(20).mean()`，结果把不同股票的数据混在一起算。
记住：**`rolling` 之前一定要确认是按股票分组的。**

**这个池子有严重的幸存者偏差** —— 它们都是"今天还活着且活得很好"的公司。
用这个池子回测，等于提前剔除了所有暴雷的、退市的票，收益必然虚高。

我故意保留了这个缺陷，因为：

1. 完整的历史成分股数据很难免费拿到
2. **你需要亲手踩一次这个坑，才会真正记住它**
